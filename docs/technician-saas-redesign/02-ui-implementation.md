# Technician SaaS implementation

The existing authenticated `/admin/bookings` route renders `TechnicianWorkspace` only for the technician role, keyed by actor/branch. Owner/manager bookings and the existing authorised Professional Services catalogue remain. The sidebar/search/notification tray/account/logout shell is unchanged. Home/Jobs/History/Profile live at `?view=...`; actual `bookingId` detail deep links survive refresh. No new app, authentication system or booking store.

Home follows the approved main/right hierarchy: four compact actual counts, next assigned appointment, today’s scheduled jobs, an explicit assignment-preference switch, separate connection readback, contextual quick actions and scheduled progress only with a nonzero canonical denominator. Desktop columns are about70/30, stack under1200px, and compact cards fit320px. Existing logo/tokens/type and restrained icons replace the mockup's unverified service photo. No fake technician name, profile photo, illustrated counts, copied dates, ETA, service guideline resource or decorative cylinder.

The additive `technician.snapshot` projection derives own next appointment, today's first5 jobs/totals, completed_today and upcoming in Africa/Lagos. Unknown terminal timestamps make the daily completion count unavailable. Scheduled progress explicitly uses scheduled-today completed statuses excluding failed/cancelled, not claimed actual completion timestamps. Next appointment prioritises existing active work, then earliest schedule and excludes terminal/declined records. Primary action opens review; it never starts work from a card.

Jobs uses paged20 actor-scoped `technician.jobs`, escaped reference/service/customer search, active/assigned/in-progress/upcoming filters and current server status. History uses only canonical `past` terminal records with bounded date periods; scheduled dates and missing terminal dates are labelled separately. Detail reuses canonical `BookingCard` and adds its existing versioned acknowledge/decline workflow. The existing quote, independently approved work, materials, checklist, private upload, immutable report, customer acknowledgement and history remain in job context. A discovered restricted DTO compatibility bug was repaired by optional rendering of intentionally omitted cash collections; no cash data is exposed.

Web applies the same existing `technician.restrict` session cutover used by native. Job forms are disabled during stale/read failure states. Twenty-second reads, abort/generation controls, actor/branch keys and foreground refresh prevent late responses from replacing current records. Retained detail forms preserve drafts during a failed read and recovery; no persistent web offline queue is invented. Generic incident-management, financial, fleet and stock administration are not exposed. Server mutation rules remain authoritative.

Profile shows own name/email/branch/account status, read-only qualification verification/expiry, existing own-name and reminder preference forms (including preserved quiet hours), Light/Dark/System and existing account/security/support destinations. Actual independent verifier validity is now returned for own qualifications, rather than inferring verification from expiry alone.

Native reuses existing `TechnicianWorkspace`, `TechnicianScreens`, `Appointment`, SecureStore auth, account/job-scoped encrypted field queue and four tabs. Home now uses the same daily/next-job/today projection, compact4-card layout, contextual quick actions and truthful scheduled progress. Jobs defaults to active, Upcoming is supported by the shared existing read facade, and closed records stay in History. Qualified profile labels use the server's independent verifier state. Decorative cylinder/waves removed;48dp header controls and pull-to-refresh added. Existing detail/evidence/report/offline/navigation flows retained. Nested local iOS shell inherited plugin paths were repaired without changing the production/local URL guard.

Actual browser evidence covers all four views, paging24 jobs across20+4 rows, search, deep link/refresh, unpaid work rejection, private DTO compatibility, terminal-only cancellation history, foreign technician denial, empty state, Light/Dark/System,320–1920px content bounds and timeout/stale draft retention/recovery. Native exports and unsigned simulator iOS/Android Release builds pass. Installed/native physical acceptance remains outstanding until actually exercised; builds alone are not device evidence.
