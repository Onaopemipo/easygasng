# Inventory and finance audit trail

`governance.audit` appends unique event ID, authenticated actor ID, action, target, outcome, timestamp and structured detail. New events retain actor role and branch at action time plus operation-specific branch, previous/delta/new quantities, reason, approval/reference or export filters where applicable. Historical rows missing role/branch metadata are preserved without invented backfills.

Audited actions include receipt, adjustment/count submission/activation/failure, protective quarantine, held return/release/disposition, transfer dispatch/receipt/cancellation, supplier/purchase changes, qualified inspection/qualification verification, expense submission/record/payment/reversal, scheduled/current report views/exports, incident assignment, existing staff/approval/settings changes and rejected protected operations. Correlation is through immutable operation/request/receipt/reference IDs and originating ledger/incident records. Failed unauthorised actions are recorded outside the rolled-back business transaction; conflicts record only action/code and actor metadata, without raw request payloads.

Audit events, stock/gas movements, receipt evidence, expense events, transfer receipts, stocktake counts, approval decisions and setting versions have append-only triggers and/or restricted UPDATE/DELETE grants. Application administrators have no erase/edit endpoint. The trusted server role cannot update historical immutable rows. Database owners remain privileged and require separate operational access control/backups; tamper resistance is not a cryptographic immutability claim.

Audit listing remains owner/technical-administrator access under existing controls; the new business audit export is owner-only. Financial exports check and audit current scope. Retention/deletion policy and off-host immutable backup are not newly invented or provisioned. Preserve business evidence through authorised corrections and the existing encrypted backup/restore workflow. Investigations link incident reference → source audit event → approval decisions → physical/financial movement/evidence; never publish secrets or private customer details in incident notes.
