# Tracking permissions and privacy

Customer/commercial: orders.customer_id must equal current authenticated actor; optional ID filtering is additional to ownership. Code and its expiry/hash never go to staff; only a currently valid code for an uncompleted owned order is returned to its customer. Driver: driver_id AND branch_id must match the live actor; no self-assignment, no other branch's stops. Owner/manager/dispatcher permissions and existing branch checks are server enforced; inventory may attest physical return but cannot pick up a driver's load. Only the assigned driver can confirm pickup/arrival. Normal owner/manager completion still needs the customer's code and complete handover; it is not a lost-code bypass.

HTTP order/delivery mutations require operationKey and tracking version. Persistent operation results bind actor, current role/branch, action and canonical payload hash; mismatched/cross-actor replay conflicts. Driver completion requires current assignment/attempt, verified pickup, non-expired code, bounded guesses, full handover and actual collected cash. Incorrect-code rate counters/audits intentionally persist outside the aborted business transaction. Raw codes are not logged by application code; synthetic browser fixtures are not production evidence.

New tables have RLS and private-server policies. Append-only triggers prevent proof/history edits; restricted runtime grants cannot alter evidence or outbox identity. No anon/authenticated Data API access or new human role grants were added. Reviewed against the official [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security); database/bootstrap restricted-role tests provide executed local evidence. Changelog markdown fetch was unsupported by the web tool; no Supabase SDK or hosted API feature was introduced.

GPS is fail-closed: no location collector, background permission request, provider credentials, storage, external routing ETA or other-stop positions are present. GPS activation is BLOCKED until approved provider, driver/customer notices/permissions, retention/deletion rules, device lifecycle/battery/jump tests and independent privacy/operational review. Full GPS collection is not claimed implemented.

Optional photos and public share links were not added. Lost-code/accessibility fallback remains restricted: dispatch/support review is available, but no supervisor override can mark delivered without normal proof. A separately reviewed shared-approval policy and implementation are still required for alternative proof. Do not grant a broad override as a workaround.
