# Live dashboard security

Local-compatible Server-Sent Events at `/api/business-live` send committed, scoped snapshots. The initial request and every five-second update invoke normal authenticated `dispatch('business.snapshot')`. There is no direct browser database connection or raw change feed. Strict branch/filter validation rejects forged scopes or extra parameters before starting the response. Current user/session/role/activity/branch are reloaded at each update; expired or suspended sessions receive a `revoked` event and the connection closes. Revocation detection is bounded by the five-second update interval, not claimed instantaneous.

Financial/cost fields are omitted according to the same server-side role checks as ordinary queries. Sales receive no serialised-cylinder, stock-operation, held-stock or movement detail from snapshots. Events carry scoped references/type/time and authorised links, without customer addresses/phone/email. Payment/expense activity is restricted to finance/owner. Session cookies are HttpOnly; no credential is embedded in an event or URL.

Content hashes deduplicate identical snapshots; heartbeat confirms freshness. The UI replaces authoritative state instead of appending events, so reconnection cannot double-count transactions. EventSource reconnects; a 30-second authenticated fallback refresh is active. Errors clear protected cached state. Role/scope changes clear generated report state. No sensitive snapshot is stored in localStorage. Server responses use no-store and no proxy buffering. Maximum three concurrent live connections per token per running application instance; this is not a distributed gateway limit.

New connections always receive a current authorised snapshot, not another subscriber's cursor. There are no transferable subscription IDs; unknown parameters are rejected. Each old connection checks its own original session again. Snapshot tables/ledgers are private and RLS-protected at the trusted-server boundary.

Actual HTTP tests verify unauthenticated/forged-branch refusal, an authorised initial snapshot without financial leakage, and an already-open connection ending after suspension. Existing actor tests cover expired/revoked sessions. Multi-process scaling, reverse-proxy buffering/load, deployment TLS and independent PostgreSQL acceptance remain unverified. See the security verification report for exact test status.
