# Tracking recovery and rollback

Emergency restriction: set EASYGAS_TRACKING_MUTATIONS_ENABLED=false and restart the affected runtime. Tracking reads/history remain available; fulfilment mutations fail closed. In production, writes are disabled unless this flag is explicitly true after separate release approval. This phase does not authorize production activation.

Ambiguous timeout: retain the UUID operationKey and exact original payload. GET /api/tracking.operation?key=<UUID> using the same actor/session scope. COMMITTED returns the immutable prior outcome; NOT_FOUND permits retry with the same identity. Never generate a new operation to guess whether stock/cash committed. Dispatch UI attempts outcome recovery; native queued proof retains its original key and version. Cross-actor or changed payload conflicts require review.

Concurrent/stale assignment: refresh the authoritative order and branch capacity. Do not remove reservations or force a state. Failed/returned deliveries require physical receipt, current cylinder eligibility and fresh capacity checks. Wrong/expired proof: contact dispatch; do not mark delivered by generic transition. Lockouts reset after the server rate-limit window. No unreviewed supervisor bypass exists.

Worker crash/message failure: rerun the existing worker with a separately owned database connection, or maintenance on the running app. Outbox notification and publication mark commit atomically; existing order history remains committed. External messages are still not connected. SSE reconnects reconcile complete snapshots; offline display is stale, not evidence of a completed action. GPS outage has no simulated fallback: location/ETA stay unavailable.

DB outage/manual fallback: stop dispatch and proof writes. Authorized operators can record a paper incident under a unique OT-<branch>-<date>-<sequence> registry reference, actor, order reference, observed physical custody/quantities and next action. No offline paper entry authorizes stock reissue, delivered status or financial settlement. A second operator reconciles the log with restored authoritative order, existing operation outcomes, stock and custody before any supported mutation. Preserve the reference in the operational note/audit; avoid duplicate business effects. An actual operator exercise and registry owner remain unassigned/unexecuted.

Migration failure: transactional migrations roll back uncommitted DDL. Keep 040–042 additive records and their audit history after commit; never use down/drop SQL to erase fulfilment. Back up before any managed migration. Fresh bootstrap/restricted runtime and encrypted isolated restore tests cover the local path. No hosted migration has been applied. Source rollback requires a verified prior runtime AND matching clients; this repository has no Git commit baseline, so Git reset is not a rollback procedure. Preserve the new tables/history and review client operation/version compatibility before restoring a previous source artifact.

Restore evidence: TRK-31 encrypts and reloads a separate PGlite image containing delivered status, proof, operation result and outbox, and verifies immutable history. It does not establish production PostgreSQL restore performance. Actual backup/restore owners, recovery artifact, RPO/RTO, retention, process-kill drills and release rollback rehearsal are UNKNOWN/NOT_TESTED; they remain release blockers.
