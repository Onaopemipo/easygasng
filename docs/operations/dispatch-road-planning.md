# Governed dispatch road planning

Road planning extends the canonical orders, users, branch trips, GPS evidence and shared Approval Centre. Migration063 adds immutable destination revisions and immutable estimate evidence; it does not seed business coordinates, rates or vehicle stock. Routing and messaging providers remain OFF. Existing production NO-GO remains.

1. A trusted operator configures an OSRM-compatible HTTPS processor origin in EASYGAS_OSRM_ORIGIN and explicitly enables EASYGAS_ROAD_ROUTING_ENABLED only after its customer-location processing is accepted. Do not use an unreviewed public demo for customer coordinates. The adapter never accepts client-supplied provider URLs, follows redirects or invents a straight-line road estimate. The official contract is https://project-osrm.org/docs/v5.24.0/api/.
2. In Settings, propose `dispatch.routing` for the branch: explicit fuel cost per litre in kobo, other operating cost per kilometre in kobo, minutes per stop and maximum acceptable road snap metres. Independent finance approval is required through the existing Approval Centre. All rate fields start null and the policy starts disabled. Explicit zero other-cost/stop allowance is allowed; enabled policy requires every field. Vehicle creation supports an explicit positive estimated fuel-consumption rate; configure a genuine rate before trip use.
3. Dispatch verifies the complete current delivery address and records its latitude, longitude and evidence using Confirm destination pin. Recent password verification, current order version and current pin revision are required. Each revision is bound to the complete original address hash. Changing an address invalidates the old pin; prior pins remain retained.
4. For each candidate driver, Calculate road plan requires an active suitable branch trip, consenting driver and an observed fix under120 seconds old with accuracy at most100 metres. Every already assigned/out-for-delivery stop and the candidate must have a current confirmed pin and a dated numeric delivery window. At most24 stops can be planned. Windows use Africa/Lagos (+01:00); deadline order is deterministic. This is a deadline-order road plan, not a traffic-aware optimizer or guaranteed arrival promise.
5. The provider request runs between transactions. The final transaction reauthenticates and rereads/locks current trip, vehicle, branch, policy and stop basis. A change rejects the estimate. Estimates expire when the original GPS observation reaches120 seconds, retain the complete stop plan, expected arrival/slack, driving distance/time and whole-route operating cost. They never change the customer's delivery fee, record fuel expenditure or make a financial posting.
6. Optionally reference that estimate ID when assigning/reassigning its candidate order/driver. The backend rejects expired, foreign or changed-context estimates. Existing payment, stock, cylinder, custody, vehicle capacity and fulfilment guards still run. Without an estimate, manual assignment requires its existing reason and records `routingMode: manual`; automatic assignment remains disabled.

Lost response: retry the same operationKey. A committed estimate is returned without another provider call; it remains an historical result and its expiry still applies at assignment. Uncertain/unavailable routing returns an error, not an invented ETA. Destination revisions and estimates cannot be edited/deleted. Rollback must preserve them and063 migration history; disable the provider/policy before changing application versions. Do not restore stale financial/stock data.

Executed fixture tests cover units/time windows, invalid paths/snap/response size, default OFF and trusted origin, real shared finance policy approval and no-self approval, destination revision replay, changed address/trip, provider-outside-transaction behaviour and immutable history. Disposable PostgreSQL independently confirms concurrent pin revisions serialize. Real road-processor activation and dispatch browser/business/operating-rate acceptance remain open.
