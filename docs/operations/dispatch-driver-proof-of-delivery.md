# Dispatch, driver and proof operations

Customer: /orders or /track shows committed snapshots, actual price/address/window, driver name when assigned, event history, last update, failure/help route and explicit GPS/ETA unavailability. /track?orderId=<UUID> remains subject to ownership. Delivery change requests open the existing support form with an order association; the server verifies ownership/branch. Requests do not automatically change a delivery.

Dispatch: /admin/orders preserves existing order inspection, item and finance controls; /admin/deliveries adds searchable/branch-filtered queues and limited real event-derived dispatch-duration metrics. Queues include placed, confirmed, preparing, unassigned, ready, dispatched, delayed after the actual Lagos-time window, failed, physically held returns, delivered and cancelled. Driver options come from a minimal authorized driver query with active-stop counts. Current window capacity remains governed by backend settings; the server, not a dropdown, determines eligibility.

Driver: existing assigned-work navigation is preserved on web and Expo. Compare physical items, gas quantities and cylinder serials to the displayed manifest; submit pickup with actual inspection notes; dispatch only after server pickup acceptance. Arrival is a separate event. Use explicit navigation link if desired. Request dispatch help records a branch-owned operational incident. Failures are recorded with reason/owner/next action and surfaced as incidents. Native pending delivery records remain encrypted and pending until server acceptance; stable operation identity/version accompanies replay. Native device/lifecycle/offline acceptance is still NOT_TESTED.

Proof: obtain the current customer code only after handing over the entire verified load. Explicit handover attestation, code expiry/guess limits, current driver/attempt, branch/capacity/stock/cylinder checks and cash amount all apply. No partial completion, photo placeholder or one-button proof bypass. Collected cash is not verified payment.

A failed physical pickup must be received in full by authorized inventory/owner with manifest and condition attestation before reassignment/cancellation. No consumed stock is restored merely because an order is cancelled. Unsafe/damaged returns stay blocked for qualified inspection; there is no automatic quarantine-to-sale or return shortcut. Structured failure reason/severity/customer-safe message/owner/next-step evidence is implemented. Alternative proof and comprehensive unsafe-return reconciliation remain subject to the safety review in the blocker register.
