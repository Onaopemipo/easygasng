# Technician four-screen integration

6 November 2026. Repository audit preceded edits; see [preflight](../reports/technician-mobile-preflight.md). Extend the existing dedicated Expo technician shell and App role routing. No new customer, booking, technician, finance or inventory system. No migrations or production data writes.

`TechnicianWorkspace.tsx` retains details, assessment, quotation and guarded `Services.Appointment`. `TechnicianScreens.tsx` supplies Home, Jobs, History, Profile and supporting account/job-picker views. `TechnicianBrandHeader` uses the existing HD logo, neutral initials and canonical unread count. Existing cylinder artwork is the approved fallback; it is green rather than the reference's orange cylinder. No fictional staff codes, avatar, ratings, jobs or money copied from screenshots.

Existing `professional-services.ts` snapshot is extended through `technician-mobile.ts`. New read facade `technician.jobs` joins the same service_bookings, slots, users and events; returns20 light rows/page plus uncapped totals. Strict input allows text, canonical status filter, dates, page, location and job-picker intent. Summary and paged list execute in the existing read-only repeatable-read transaction pattern so totals and rows share a committed snapshot. Scope always comes from the authenticated current technician and active branch. User/branch overrides are rejected. Existing `bookings` keeps its array contract and adds an optional strict own-ID selector so deep links and older history are not limited by the original100-row default.

Summary counts use all scoped bookings. Completed-this-month uses actual completed events in Africa/Lagos; missing terminal events make this metric unknown. Ratings use existing service_feedback only for the booking's verified customer and current completed technician assignment; no feedback means null. Unread total is independent of me's30-notification display cap. A future rating attribution policy for reassignment after completion requires business review; no historic technician identity is invented.

Availability reuses the existing audited/idempotent command and active-visit restriction.30-second foreground polling and foreground refresh provide controlled refresh, not a promise of live connectivity. Last successful sync is visible. Failed refresh disables availability until confirmed. Selected detail is refreshed through the scoped selector. Server checks remain authoritative for every mutation.

Integration boundary: customer, driver, admin and inventory components unchanged. API route adds the read endpoint and per-user minute read budgets. No additional privileged session scope. Comprehensive technician durable offline evidence/revocation replay remains an engineering gap, explicitly retained in the matrix.
