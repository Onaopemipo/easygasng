# Events and live tracking

Additive migrations 040–042 extend existing orders/order_events, create delivery_attempts, immutable delivery_evidence and order_event_outbox, add operation correlation/unique event versions, and associate support tickets with orders. Existing business_operation_results provides actor/action/role/branch/payload-scoped persistent outcomes; no duplicate stock/payment ledger was introduced. database/bootstrap.sql is regenerated for fresh installations. Existing local getDb applies additive upgrades to revision 42; managed PostgreSQL requires an explicit separately approved migration. No hosted database was changed. Supabase CLI/mirrored hosted migration packaging was not executed; CLI is unavailable and hosting remains outside this local rollout.

/api/tracking/stream authenticates with the existing cookie or bearer session and serves complete committed snapshots. Each five-second heartbeat revalidates current session, role, branch and driver assignment through the existing orders dispatcher. Connections close around 50 seconds and EventSource reconnects; no transaction is held across network waits. No public sharing token or predictable-reference access was introduced.

This transport is snapshot reconciliation, not a durable delta broker: no Last-Event-ID replay claim. Full snapshots include immutable event history/version; clients reject lower versions and remove records no longer in the authorized snapshot. Equal-version payment changes remain observable. Account-generation guards prevent a late old-account fetch from replacing a new account's state. Customer history is limited to the latest 100 by default; an authorized ID query supports direct detail retrieval.

Event insertion commits an outbox row in the same business transaction. Existing runJobs/maintenance invokes publishTrackingNotifications in a separate transaction, SKIP LOCKED, inserts baseline in-app notifications and marks those events published atomically. A worker transaction failure cannot undo a previously committed order. Notifications are retryable; no exactly-once external email/SMS/push claim. Existing providers stay unconnected. Process-kill/network partition and proxy/load drills remain unexecuted.

Snapshot serving currently performs per-order enrichment queries; a production-sized subscription/load test and query optimization gate remain open. GPS collection/routing is not connected; responses explicitly return enabled=false, unavailable location and null ETA. There is no simulated marker or computed routing ETA.
