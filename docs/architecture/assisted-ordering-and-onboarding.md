# Assisted ordering and progressive onboarding

Current: users remains the single identity model. Migration047 assigns an immutable opaque EGC identifier to existing and future customer/commercial records; it is a lookup key, not a secret. Existing email-backed registration and sessions are unchanged. Legacy phone addresses are searched in normalised form without rewriting or merging them. `customers.lookup` is owner/manager/sales only and branch scoped. Duplicate matches require human record confirmation. `customers.provisional` serialises by phone with a transaction advisory lock; synthetic `.invalid` mailbox is an internal non-deliverable identity placeholder, not a verified contact or a test customer. It cannot establish possession or activate an account.

`order.assisted.create` uses real customerId while the authenticated staff Actor remains unchanged. Shared checkout performs current quote/location/branch/stock/cylinder/capacity/payment policy checks and emits customer-owned notifications. Staff cannot spend customer wallet/rewards. Source and staff attribution are immutable. Existing retries remain compatible because nonfinancial source metadata is excluded from request fingerprints. Backend accepts existing multi-line limits; the first admin form currently supports one gas line and one product. Phone numbers are not authentication secrets; no lookup returns a session.

Outstanding: one-time order-completion links, hashed short-lived challenge, revocation/resend, attempt limits, OTP possession before display, optional-field progressive onboarding, same-ID activation, returning-customer reorder and real conversion events. Do not bind a new email or mark phone verified without possession proof. Unconnected providers block live sending, not implementation of these missing contracts.

Operators: Orders → Create phone-assisted order → find caller or create provisional record → confirm real address/area and capacity → review current quote → confirm only after caller instruction. An unconfigured delivery/payment/stock policy correctly rejects. Do not enable configuration just to test a real caller. Account & privacy displays the public ID; Customers searches/exports it.
