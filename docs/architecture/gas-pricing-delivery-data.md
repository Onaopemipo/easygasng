# Gas pricing, delivery and data integrity

Application migrations 023, 025 and 027 extend the existing schema; managed policy 024 adds private-schema runtime grants. The corresponding CLI-generated managed migrations are `20261029161100_shared_approvals_gas_delivery.sql` and `20261029162826_gas_reporting_snapshots.sql`. `database/bootstrap.sql` is regenerated for fresh installations. Existing order amounts, stock quantities and financial ledgers are preserved.

`settings`, `setting_definitions`, `change_requests`, `approval_decisions`, `setting_versions` and `audit_events` remain the authoritative governance records. New price and location keys use them. `delivery_locations` holds the projection of each approved location version. New addresses reference stable location IDs and store recipient/building details; default addresses use a partial unique index. Orders retain location, pricing and address snapshots and an operational-review flag.

`gas_stock` uses integer grams with non-negative and reservation bounds. `gas_stock_movements` is an append-only unit-specific extension to the inventory ledger, in the same database and transactions. `order_gas_lines` snapshots capacity, actual requested grams, price per kg, subtotal and pricing version; it also records verified cylinder identity, filling allowance and inspector evidence. Existing inventory/order-item records remain authoritative for physical goods. A legacy order line receives inferred gas grams only where its original stored label explicitly identifies a fixed kg refill; monetary amounts are never recomputed using current prices. Ambiguous historical labels remain unclassified rather than fabricating gas quantities.

Reservations serialize on the selected fulfilment branch, then lock pricing configuration and relevant location/stock rows. Gas stock is reserved with a conditional update. Confirmation checks accepted pricing versions and total, active branches/locations, delivery capacity and stock within the transaction. Cancellation releases and completion consumes reservations with unique ledger references. New gas sales cannot use the old fixed-price POS path. Serialised cylinder allocation, quarantine, inspection, custody and reissue safeguards remain enforced. New customer intakes enter quarantine; no safety clearance is inferred from capacity.

Activation locks a request and current setting, revalidates its policy snapshot and independent decisions, and uses a savepoint for the setting and projection changes. Failure rolls those changes back while persisting FAILED and protected diagnostics. A unique request-to-version index prevents duplicate activation. New table RLS is enabled in the unexposed managed schema; runtime grants omit DELETE and immutable financial/audit updates. Multi-connection PostgreSQL verification is still required; local PGlite serialization is not presented as proof of production lock behaviour.

Migration 027 adds the confirmed Cylinder Maintenance offering as an inactive, quotation-only draft with an empty checklist. Its commercial configuration, scheduling and qualified safety checklist require the existing independent approvals before bookings open. The managed migration is `20261029203712_cylinder_maintenance_draft.sql`. Existing service configurations are preserved.
