# Approved customer functionality design

The twelve-screen collage is the layout authority. Sample orange cylinders/portraits, customer IDs, balances, map routes, driver identity, dates, prices and notifications are not data sources. Reuse approved existing cylinder/logo assets; do not claim identical unavailable artwork.

Home now has the official HD logo, real greeting/initials, exact unread count from customer.dashboard, green order hero, six working shortcuts, history-dependent refill state and independent refresh/retry. Customer tabs are Home / Orders / Services / Wallet / Account. Existing staff tabs are unchanged. Nested headers have Back and actual screen labels; safe native destinations use an allowlist and retain sign-in return intent. Existing subflows remain reachable.

Order Gas retains the canonical quote/checkout form, adds visual configured capacities, preserves decimal input text and uses shared gasLine policy validation for totals. Capacity never implies quantity. Checkout presents only configured methods; no Paystack sample choices or paid state. Tracking shows real event timestamps/driver only as returned by server, with explicit unavailable GPS/ETA and preserved visit evidence/history.

Services restyles active catalogue into rows while retaining selected service, qualification/slot and quotation/booking handlers. My Cylinders reads actual owned physical records separately from consumption profiles; register submits an inspection request, not an inventory/custody mutation. Refill plans remain existing product-linked reminders, with active/pause/cancel forms and no automatic payment consent invention.

Wallet is ledger-derived purchase credit, with transactions and rewards/credit navigation; funding/transfer omitted. Invoices list actual issued records, read current approved corrections/balance, and download private server-generated PDFs via authenticated header and temporary native cache. Receipt documents honestly unavailable. Notifications group actual messages by Lagos date with read action and allowlisted related destinations. Account preserves stable ID, addresses, privacy, support, rewards and sign-out.

Semantic tokens extended for elevated surfaces, buttons, error/success, input, overlay, skeleton and chart. Shared CustomerUI controls use tokens, min48 targets and scalable min15 text; existing modules still use the compatibility theme bridge. Full visual fidelity, all populated state/contrast checks, tablet/physical-device and native hosted-provider appearance remain unverified. Onboarding/splash untouched.
