# Business Owner automatic approval

User instruction (10 November 2026) explicitly changes the business approval policy for owner-origin requests. “Admin” is mapped to the Business Owner role visible in the supplied screenshot, not the separate technical administrator role.

Existing propose/submit/rollback/activation are extended. Server flag EASYGAS_OWNER_AUTO_APPROVAL=true enables the authorised policy per installation; default OFF preserves other deployments. New owner submissions automatically record immutable authority evidence and enter the existing activation process. Drafts stay inactive until submitted. Existing own pending requests expose Apply my request; GET requests and rollout never mass-approve old records. Inventory one-time operations bind their existing request metadata before activation, avoiding partial or duplicate postings.

Authority evidence is bound to requester, revision and base version. Live active owner authority, role/scope permission, recent identity verification where required, setting values, optimistic version, expiry, effective date and rollback source remain checked. Staff requests keep independent review. Technical administrators cannot impersonate an owner. Owner approval of a safety checklist records only the owner part; an independent currently qualified safety reviewer remains mandatory. Customer agreements, pre-work payment gates, verified payment/provider requirements, live-payment blockade and stock constraints are not bypassed. Scheduled changes remain scheduled until their day and activation checks pass.

UI shows the owner pending action and status-specific new submission feedback. It never describes an activation failure, superseded request, saved draft or outstanding qualified review as an applied change. No data schema migration, account reset or bulk approval is required.

Evidence: 40 focused tests (including six new cases), types/build and real PostgreSQL concurrent submission/repeated-application test pass. Full regression and hosted rollout/actual UI acceptance are tracked in the RTM. No operational request has been applied by these tests. Production NO-GO, retain-all, historical import hold and native/server-build deferrals remain.

Rollback: redeploy prior source to remove the new behavior, or set the server-only owner policy flag false and redeploy. Do not delete audit evidence or active versions. Disabling the flag prevents future automatic approval and blocks outstanding automatic-authority activation unless normal review is supplied. Previously active values remain recorded. The demo's existing background-job configuration is unchanged; future-dated approval is immediate but activation still uses the existing scheduled activation worker/manual control after the date.
