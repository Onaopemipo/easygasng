# Security and finance regression

The public availability response includes slot identifiers, start and end times, catalogue version and a reason code. Staff names, qualification evidence and private bookings remain outside the response. The read checks active branch and service, supported coverage when an area is supplied, independently verified qualification through slot end, technician availability, matching duration, and non-overlap with active bookings. Detail availability additionally requires the configured booking checklist. Existing rescheduling reads retain the original array shape.

Existing server locks and customer/booking idempotency remain in force. Web and native revalidate selection before review. Direct confirmation preserves the existing idempotency replay path, then applies the current server checks for a new request. Staged requests revalidate the slot and current bundle, and take displayed bundle amounts from the existing bundle response. The combined booking transaction still revalidates its own inputs.

Existing qualification review, safety and report acknowledgement gates, quote approvals and revisions, payment verification, inventory, wallet, Paystack, refunds, POS and accounting behavior remain governed by their original server paths. Full regression and the focused booking, authorization, quote and financial tests provide local evidence.
