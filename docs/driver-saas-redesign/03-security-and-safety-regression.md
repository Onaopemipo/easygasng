# Security and safety regression

No server model, database migration, provider configuration, permissions or operational flags changed. `protected-business-sources.json` records baseline hashes for 18 canonical finance, dispatch, custody, evidence, offline, GPS, shared app and technician modules. DRVS-PRESERVED executes those comparisons. DDI-AUDIT01 retains its earlier baselines and adds a separately reviewed single-file allowance for DriverWorkspace in approved-field-source.json; financial and non-driver hashes are unchanged.

Executed negative controls include restricted driver denial of legacy cash/sales/stock access and invented transitions; customer denial of driver APIs; cross-branch and removed-attempt denial; expired acknowledgement; unverified payment/revoked COD; missing serial allocation; capacity/custody/physical mass; consented current GPS, observed-time recency, private proof ownership/retention; and immutable/idempotent ledger, stock, custody and evidence actions. The full PostgreSQL-enabled suite and named driver tests are in evidence/full-regression.txt. A synthetic History contract test inserts isolated closed rows to test paging; it is not physical completion evidence.

The new DRVS-SCOPE test removes the current driver's assignment and deactivates its branch, proving authoritative reads disappear/deny rather than widening access. DRVS-DATA distinguishes malformed/missing values from true zero; DRVS-CONTACT tests fresh/stale/unknown independently of GPS and availability. DRVS-NEXT rejects terminal/rejected attempts without mutating source. Existing encrypted field-queue, proof capture/upload, trip lease/consent and vehicle custody code are preserved byte-for-byte.

The actual local Chrome test additionally verifies customer API 403; active-work availability 409; one request after a duplicate tap; server-confirmed empty-driver availability on/off; read-only offline, 429 and real 15-second read timeout; recovery; and 401 history denial clearing driver UI through the existing sign-in redirect. HTTP 429/401/timeouts are browser-injected failure responses, explicitly not a claim of provider outage or real token expiration. Own assignment/history data and actions come from the disposable local PostgreSQL backend.

Installed iOS verification shows available=true while OS foreground/background GPS are Not granted, backend connected and trip sharing No active trip. This proves those displayed signals are independent in this fixture; it does not prove real-phone background tracking. History detail showed only reference, declined outcome and actual timestamp, with no old customer contact.

No newly reproduced canonical business defect remains in the executed scope. This is not safety/finance/production sign-off. Real-phone locked-screen capture, camera/permission interruptions, airplane/reconnect replay, Android hardware back and assistive-technology acceptance remain unexecuted. Earlier production NO-GO, verified-delivery-boundary, physical stock/inspection, provider/merchant, and Excel import holds remain in force. Demo fulfilment and Paystack sandbox were not changed by this phase.
