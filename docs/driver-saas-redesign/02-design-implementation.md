# Driver design implementation

Source commits: `a97f4de` (isolated local driver configuration repair) and `274e75e` (driver presentation). Baseline `904fc6b`; branch `codex/driver-saas-redesign`. Existing `/admin/deliveries`, left navigation, account/search/header and driver-role entry in App.tsx remain. Home / Orders / History / Profile are internal destinations, not new privileged routes.

Web uses a constrained 1440px content area, a primary/right-column desktop composition, a compact greeting, actual scoped metrics, next assigned delivery, loaded-assignment list, separate availability/contact/GPS/trip fields and contextual actions. Availability leads the mobile reading order. Lists become cards; filters wrap. Browser measurements at 320, 390, 768, 1024, 1440 and 1920px found no page or workspace horizontal overflow in any of the four views. Existing light/dark/system preference, visible focus, minimum 44px controls and reduced-motion styles apply.

Native reuses DriverWorkspace and its original delivery states, App entry, safe areas, Android back and encrypted queue. DriverSaaS.tsx supplies the forest/lime header, simple wave accents, cards, badges and four-tab bar. The Home availability panel is approximately 132pt tall in the installed iOS simulator, compact compared with the supplied large photograph concept (the exact requested 35% comparison remains unverified); it uses a compact switch and confirmed status instead of a photograph. The existing minimum text size/dynamic scaling remain. Backend contact, OS GPS permission and trip sharing remain distinct. KPI values are real server aggregates; missing/stale data is Unavailable. Scroll remains vertical, with bottom padding for navigation.

Orders show only the returned owned/current attempts. The pure next-assignment selector prioritises active progress/arrival, excludes closed/rejected attempts and never mutates source records. Actions open existing assignment, pickup, progress or handover details rather than skipping transitions. Native detail/back preserved the selected In progress filter in actual simulator verification. Lists retain filters/scroll on detail return. Web acknowledgement/decline remains the supported existing capability; serial inspection, trip, pickup and proof workflow stay in native.

History uses the existing closed-only 20-row API, Lagos date and outcome filters, accurate totals and an explicitly current-page reference search. The backend intentionally omits historical customer identity/address. Therefore the mockup's old customer destination, item quantities and expanded timeline are omitted where absent; these are recorded scope deviations, not fabricated data or new privileges. Private proof remains available only through the retained authorised/retention-checked action.

Profile uses actual name, initials, branch, contact and account status. Only the name can be edited through account.update. Current-trip vehicle and absent verification/documents remain read-only and honest. Existing notifications, support, security, theme, permission guidance and safe queue retry are retained. No new sync/required-alert opt-out exists. Unknown queue count does not become zero.

Read-only snapshot/history/proof requests have a 15-second deadline. Failures retain a visibly stale, read-only state. Authoritative permission/session denial clears protected cached state; web's existing global 401 path returns to sign-in. Mutation idempotency and canonical guards are unchanged. A synchronous busy lock suppresses duplicate taps; availability changes only after server confirmation.

Unsupported mockup elements were deliberately omitted: Earnings, duplicate Deliveries/My Orders, unassigned claim queue, QR scan, fabricated route/map/ETA, yesterday trends, stock/cash/vehicle administration, driver ratings, compliance uploads, unverified badges, language switch and fake photo. No new provider, native dependency, schema, operational flag or payment setting was introduced.

The inherited `./plugins/...` entries failed when Expo resolved the dedicated nested driver project. app.config.js now resolves the same two existing parent plugin files with absolute paths; the local-only profile guard and production identifiers are unchanged. This separately reviewed repair enabled actual iOS and Android release compilation.
