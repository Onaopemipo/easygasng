## Cleanup safeguards

`App.logout` now invalidates current account/session references and clears visible private state immediately, captures only the ending token for server revocation, then removes the saved SecureStore session. A failed delete falls back to an empty auth value. If both storage operations fail, the login screen explicitly reports incomplete saved-session removal. New sign-in is held until storage settles, so an old deletion cannot remove a new session. Network/GPS cleanup runs independently with a five-second limit and cannot hold the signed-in workspace open. The shared helper never deletes encrypted photo/field queues. Offline server revocation is best effort; it is not reported as confirmed success. No remote-server revocation or GPS timeout is converted into a completed delivery or an evidence deletion.
