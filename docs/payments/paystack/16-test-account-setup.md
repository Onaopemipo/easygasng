# EasyGas Paystack test account setup

Status: account setup required (user confirmed6 November2026). No secrets supplied and no activation performed.

1. Sign in to the EasyGas business on Paystack, or create the actual business account. Keep Test Mode selected. Confirm the account belongs to EasyGas before generating credentials.
2. Open Settings → API Keys & Webhooks (new dashboard may show Developers overview). Locate API Configuration — Test Mode. This adapter currently supports the full server test secret `sk_test_…`; restricted keys are not yet supported. Hosted checkout does not need a public key in the app.
3. Save the test secret in the server's local ignored secret environment, never in Git, screenshots, mobile config, NEXT_PUBLIC_* variables or chat. Use the existing environment loader/secret flow. `.env.example` contains variable NAMES only.
4. Use an isolated disposable synthetic dataset. Do not point test payments at the original customer/business database. Runtime requires EASYGAS_PAYMENT_DATA_CLASS=synthetic, EASYGAS_PAYSTACK_MODE=test and EASYGAS_PAYSTACK_ENABLED=true. Keep disabled until the approved sandbox exercise; keys alone do not enable the DB policy.
5. Configure a reachable approved HTTPS test origin as APP_URL. Callback URL: `<test-origin>/payment-return`. Webhook URL: `<test-origin>/api/payments/paystack/webhook`. Paystack cannot deliver to127.0.0.1; use a controlled staging origin or approved tunnel. Nothing has been published or tunneled by this implementation.
6. Check the merchant's active signing scheme. Prefer new timestamped Paystack-Signature and store actual dashboard `whsec_…` values server-side in PAYSTACK_TEST_WEBHOOK_SECRETS (comma-separated active rotation keys); set PAYSTACK_WEBHOOK_SIGNATURE_MODE=timestamped. If dashboard still uses deprecated x-paystack-signature, explicitly use legacy with the test secret; do not silently downgrade signatures. Generate/rotate signing secrets through the dashboard when available.
7. Independently approve the sandbox fee schedule, channel eligibility, amount caps and merchant/customer absorption through existing Payment Gateway & Fees Settings/Approval Centre. Confirm dashboard automatic fee addition is OFF before app gross-up. Do not copy test fixture rates into real policy. Confirm Paystack permission for customer fee pass-through and closed-loop credit before any live use.
8. Start web and configured worker against the SAME isolated data source using existing supported runtime. Embedded PGlite cannot be shared by separate processes; use a disposable PostgreSQL environment for concurrent server/worker verification. Never remove a DB lock to force concurrent use.
9. Use Paystack's official test payment details, verify actual charge.success delivery in Developers → Webhooks, then inspect EasyGas committed principal, fee breakdown, receipt and duplicate replay. Test failed/abandoned/delayed/unknown outcomes and retain provider evidence with secrets/personal information removed. Do not enter real card details in tests.
10. Leave live mode and keys disabled. Test account setup does NOT clear unfinished refunds, reversals, settlements, native/checkout/operational gates or production NO-GO.
