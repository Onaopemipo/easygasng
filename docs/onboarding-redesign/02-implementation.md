# Implementation and entry

- Web `/`: the compact tour button appears near the existing homepage actions. It opens a native dialog only on activation. Skip and Get Started return to the same storefront; Escape dismisses without recording completion. Returning visitors can replay the tour. Browser-local state contains just a `seen` marker. The dialog is populated only when explicitly opened, and there is no new web route.
- Native: after initial links are resolved, verified customer and commercial accounts can see the three scenes on first eligible Home. An unauthenticated visitor can choose the tour from Home without blocking the shared staff sign-in. Finishing the guest preview records the same seen value so it does not repeat after customer sign-in. Existing `easygas.onboarding.v1` values suppress automatic repeat. Customer Appearance opens a read-only replay; closing replay does not write, delete, or clear data.
- Driver and technician shells, verified staff roles, unknown roles, and unresolved restored sessions do not auto-enter the tour. Completion returns to the previously active screen. Auth, cart, checkout, deep link destinations and permissions still belong to their existing flows. No network-dependent feature claims, provider calls or permission prompts are initiated by introduction controls.
