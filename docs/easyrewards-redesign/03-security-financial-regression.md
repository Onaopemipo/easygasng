# Security and financial regression

`rewards.summary` applies the existing customer and commercial role check, strict input validation and session ownership. Its optional referral capability is derived from approved policy, the issuance flag and the customer’s active branch. The referral actions enforce these checks again before issuing or attributing a code.

Ledger and payment values come from their existing authoritative records. Pending awards are a count of unposted events. A restricted balance removes the spending affordance. The existing checkout continues to validate offers, eligible spend, balance, caps, payment and replay. Verified order and booking references are joined to the customer’s own ledger.

Client refresh and error states disable writes. Previous confirmed data has a visible refresh timestamp after a transient error. Session expiry and role rejection clear the displayed account data. Repeated referral requests are guarded while a request is in flight. The domain retains its independent approval, privacy, stock and finance checks.
