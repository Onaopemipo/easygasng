# Cooking Gas Profiles repository audit

Baseline is commit `54b1b15` on `codex/notifications-centre`, with in-progress changes from other EasyGas phases. The Cooking Gas Profiles changes are scoped to this worktree. The Service Details phase recorded 684 passing tests, web build and both native exports at the preceding checkpoint. This phase records its own runs separately.

- `apps/web/app/[...slug]/page.tsx` allows /consumption. `apps/web/components/site.tsx` renders it in the customer shell and reuses the profile component inside /refill. The previous UI used a permanent ActionForm per profile and another for creation.
- `apps/mobile/App.tsx` opened the screen from the customer account menu, then rendered NativeSmartOffers and the consumption branch of Workflows. That branch exposed only three of five existing feedback choices. ContextSheet and the theme provider already exist.
- `apps/web/lib/refills.ts` owns the profile, history and feedback actions. Catalogue gas refill products supply permitted sizes. The profile record links a customer and product. There is no public profile archive, delete or profile metadata edit action. Verified deliveries and verified payment records are required by history ingestion. The existing forecast excludes ambiguously attributable dynamic lines and needs two qualifying refills.
- `rewards.smart-offers` uses approved branch policy, offer lifecycle and customer communication preferences. `schedules` and `schedule.authorisations` supply distinct per-customer plan and recurring authorisation records. Both must be active for a recurring refill.
- Session actors are reloaded server-side. The profile write already locks the owned active row and applies a one-hour feedback throttle. The read had no explicit customer role guard, and the write offered no expected-feedback version. Creation checked for an existing active profile without serialising concurrent creates.
- This phase keeps the original customer shell, both profile entry points and existing rewards and orders navigation. It reuses the cylinder illustration on both platforms. Authenticated desktop and responsive browser checks, installed device checks and production release are separate gates.
