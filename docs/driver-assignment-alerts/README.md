## Implementation and authority

`apps/mobile/DriverAssignmentAlerts.tsx` is mounted once inside the existing DriverWorkspace. Successful authenticated current orders and snapshot responses drive pending alerts, not notification text. `packages/business-rules/src/driver-assignment-alerts.ts` checks current actor/branch, attempt driver, assigned state, unexpired response eligibility and unresponded assignment. A SHA256 of origin/actor/branch scopes private SecureStore attempt IDs; repeated polling and account/branch switches cannot turn another assignment into a prompt. Notification payloads contain the order reference and opaque IDs only, excluding address, phone, payment details and handover codes. Native tap navigation rechecks current assignment. Stale/revoked access cannot acknowledge.

The public signed-in DTO uses `branchId`, while internal server actors use `branch_id`. The first interactive attempt exposed that mismatch: the order arrived and the bell updated, but the filter produced no popup. Normalisation now accepts the public DTO, rejects conflicting fields, and is tested against an actual `me` response. The corrected installed app displayed the real pending assignment.

Acknowledgement is explicit: driver enters a reason and taps Acknowledge assignment. The app rereads the current scoped order and snapshot, verifies attempt/version, then calls unchanged `dispatch.respond` with a stable operation key. It does not queue a false offline success, pick up goods, collect cash, mark delivery complete or change payment. Dismiss/review and inbox read remain distinct from acknowledgement. Server rejection/retry leaves a useful error. Pickup remains the existing separately guarded workflow.

Native `expo-notifications` requests permission only on an explicit Enable button. Android uses a high-importance, private lock-screen channel with default sound. Foreground alerts also play the bundled0.85-second PCM chime via `expo-audio`, gated by notification sound permission, foreground state and channel settings. Playback respects silent mode, uses no recording and does not run in the background. The foreground OS handler suppresses its duplicate default tone; a future background OS notification retains its normal sound policy. App config explicitly disables microphone permission, Android recording and background audio. Dependencies are declared in the main, driver and technician shells so shared imports cannot produce a missing-native-module crash.

Profile provides Enable assignment sound & banners, Test assignment popup & sound, and device settings. The test is clearly labelled and creates no order or acknowledgement. Native alerts depend on OS/device volume, permission and mute settings; no critical-alert or Do Not Disturb bypass is introduced.
