`documents.list` does not expose full invoice snapshots, service internal costs, tokens, provider keys or bank account secrets. Receipt lines/principal/fee/balance are projected from the same canonical model used by screen/PDF. It returns20 records/page and complete scoped match count. Search is literal (SQL parameter + position); dates use Africa/Lagos. Branch filters cannot expand customer/finance access. Existing working routes/navigation are preserved.

Status filtering derives each candidate status from the same canonical adapter, not a duplicated money/state SQL formula. Above100matching candidates it returns409 with a request to narrow dates/branch/search. It never filters one page and fabricates a total. This bounded behaviour is tested; production-volume status-query scaling remains an open gate.
