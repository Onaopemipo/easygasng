# Architecture and ownership
The native technician shell imports the same App, auth/API client, theme, secure token store and existing Services Appointment implementation. Canonical users are technicians, not a new technician registry. Service bookings, slots, catalogue snapshots, quotes, customer decisions, materials, verified payments, reports, media, notifications and audit retain their IDs and tables.

055 adds consent, expiry and content hash to canonical media and work start time to bookings. 056 adds assignment response fields to the same booking; response history remains immutable booking events. 053 adds assessment/authorised/paused work phase and quote reference to the existing booking, and willingness-to-work fields to users. 054 adds a restricted technician session capability. No order, inventory or payment ledger is duplicated. Migration/bootstrap/readiness must be advanced together; deployment is not authorised.

Independent quote reviews use the SAME generic change_requests/approval decisions/activation mechanism. Each immutable quote revision has service_quote.<quote UUID> boolean authorisation in existing governed settings. Technicians propose; independent owners approve after reauthentication. Customer acceptance remains a separate canonical decision. New revisions pause work. Fixed-price bookings without additional quote use the already governed fixed scope accepted when the customer booked; extra scope requires a quote.
