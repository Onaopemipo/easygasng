# Canonical service state and work phase
Do not introduce new competing appointment states. Existing pending_confirmation → confirmed → assigned → en_route → in_progress is retained. During arrival/assessment, work_phase=assessment. Revisions set paused. Customer quote decisions use awaiting_customer_approval/in_progress while the work phase remains paused. Explicit verified booking.work.start sets authorised with the latest immutable quote ID. Successful report moves to awaiting_acknowledgement; customer acknowledgement moves to completed. Unsafe outcomes produce the existing failed/report/incident path, never successful certification. Cancellation/rescheduling remain canonical controlled actions.

Work, material effects and successful reports revalidate authorisation. Offline status does not assert a server commit. booking.assignment.respond records versioned acknowledgement/decline, preserves assignment/capacity and notifies operations on decline. Restricted sessions must acknowledge before visit progression. Full reassignment concurrency and offline conflict UI remain unfinished.
