# Wallet repair audit — 10 November2026

User reports hosted customer wallet error, absent continuation and dense layout. Before edits: wallet funding read required users.branch_id, while self-registration can leave that field null. Paystack wallet obligations independently required the same field. Public payment configuration used a hardcoded Lagos fallback for unassigned customers. WalletFunding mounted transfer fields/hosted payment implicitly based on amount, with no initial Continue action. The wallet page eagerly mounted funding, the complete document library/filter form and a large empty transaction panel together.

Existing systems retained: account identities/default saved addresses, active business branches, branch-keyed verified receiving accounts, independent credit-request approvals, Paystack fee/verification/posting engine, document library and immutable wallet ledger. No bank account was invented, no customer branch backfilled, no real wallet credited and no payment/provider flags activated.

Correction: shared authoritative funding-context resolver uses active assigned branch, active owned default address, or an unambiguous single active business branch. Ambiguous context returns a setup action; never use another customer's address or silently change identity. Bank funding reads remain usable with historical owned requests when context is missing. Bank writes and card obligations fail closed without a resolved active context. Wallet-specific payment configuration uses the same resolver; generic order/invoice/service configuration retains established behaviour, covered by WALLET-CONFIG-SCOPE.

UI: balance plus one primary top-up action; transactions and documents are separate views. Top-up has a visible validated Continue action; only then are bank instructions/reference submission or Paystack fee review shown. Unavailable configuration and invalid amount explain why progression is disabled. Bank requests remain pending until business verification; cards still require provider verification. Existing production NO-GO, prior mobile-web correction scope and import/native-build holds remain.
