## Existing operational flow

1. Independently authorised owner/safety reviewer records actual current qualifications through existing `technician.qualify`: `bulk_lpg_metering` for the metering administrator, `bulk_lpg_loading` for the inventory issuer/receiver, and `bulk_lpg_dispensing` for the driver. A driver can only receive this specific new qualification; generic technician qualifications remain unavailable for drivers. Self-verification remains rejected. No licence/certification is inferred from the software record.
2. Register the actual LPG-suitable vehicle and begin its existing driver trip. An independently qualified owner records its calibrated **mass** meter, serial, evidence reference and expiry. Grams are authoritative; no volume/density conversion is assumed.
3. Inventory issues physically measured loaded mass and initial cumulative meter reading, listing existing assigned gas orders for that branch/driver. Orders are locked deterministically, then trip/vehicle, meter and canonical branch balance. Already reserved order gas is not reserved again. Only unallocated buffer increases `gas_stock.reserved_grams`; branch-owned total mass is unchanged. Buffer reservation is also recorded in existing gas stock movements.
4. The assigned qualified driver independently observes and acknowledges both loaded mass and meter reading. Stale version, mass disagreement, expired qualification and wrong driver reject without success.
5. At the current recorded delivery arrival, the driver can report cash actually collected for the original uncorrected COD obligation. This uses the existing pending cash collection, not a payment assertion. Owner/finance must independently reconcile through existing `cash.reconcile`; the driver cannot verify payment. Corrected/supplemental collections are rejected for separate finance review. No payment credentials or provider flags are changed.
6. Backend dispensing requires the current issued invoice balance paid, independently verified full principal, no approved refund, active suitable vehicle/branch, current calibrated mass meter, current qualification, current arrived attempt and existing cylinder ownership/test/capacity/inspection/coverage controls. Meter delta must equal the entire reserved allocation. Unallocated buffer is not a sale. Record the actual cumulative meter reading; no offline success or client-only unlock is supported.
7. Existing delivery completion still requires its original proof/handover/OTP controls. Its canonical gas reservation transaction requires the dispensing record, consumes branch mass/reservation exactly once and marks custody fulfilled. Previously reported cash is checked and reused, not inserted or verified twice. An order cancellation cannot turn dispensed LPG back into stock. An undispensed cancellation transfers its reservation into held vehicle buffer without an intermediate over-reservation or warehouse release.
8. Driver declares measured returned mass; independently qualified inventory staff physically receive it. Exact agreement with loaded minus dispensed mass releases only remaining buffer reservations, records canonical reservation movement and makes undispensed order allocations available back at the branch. Existing order reservations remain reserved. A discrepancy records immutable evidence, preserves stock/reservations and holds trip closure. There is no automatic rounding, write-off or fabricated stock adjustment.

Web: existing deliveries workspace includes meter registration, measured load issue, acknowledgement, cash report, dispensing, return declaration/receipt and custody history. Native: existing driver workspace contains the corresponding driver controls; existing tabs/navigation remain. Staff qualification and finance reconciliation use their existing modules. Full form interaction and physical-device acceptance remain unverified. The bounded summary currently returns the latest100 scoped loads; full paged custody history remains outstanding.
