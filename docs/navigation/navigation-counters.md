# Navigation counters

Read-only `GET /api/navigation` authenticates the current active user/session on every request. It accepts no role override and rejects a branch parameter different from the authenticated branch. Owners see the same global scope their existing APIs allow; other roles receive only their assigned branch. Missing or inactive branches deny non-owners. Only permitted route counters are returned; a role that can read a page but cannot act on that queue does not receive an actionable badge. Zero counts are hidden; larger badges show `99+` with the exact count in the accessible name.

| Counter        | Definition                                                                     | Source / restrictions                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| orders         | New orders awaiting acceptance                                                 | orders: status placed; owner/manager/dispatcher only                                                                                                                                                                  |
| support        | Open or in-progress support requests                                           | support_requests: open or in_progress                                                                                                                                                                                 |
| inventory      | Physical product and bulk gas balances at or below configured thresholds       | inventory joined products: unarchived, excluding legacy Gas refills, available <= threshold; gas_stock: configured threshold_grams only                                                                               |
| deliveries     | Accepted or preparing orders awaiting a driver                                 | orders: accepted/preparing, no driver; drivers never receive this branch-wide queue                                                                                                                                   |
| bookings       | Service appointments awaiting confirmation or assignment                       | service_bookings: pending_confirmation, or confirmed without a technician; owner/service_manager only                                                                                                                 |
| reconciliation | Unverified order/service cash collections and submitted POS cash discrepancies | cash_collections and service_cash_collections without verifier, plus submitted POS shifts with a counted/expected discrepancy; owner/finance only                                                                     |
| approvals      | Unexpired requests awaiting your independent decision                          | change_requests joined setting_definitions: current view/approval roles or valid bounded delegation, unexpired pending/partial, no self/recipient/previous revision decision; qualified safety reviewer when required |
| incidents      | Open or acknowledged operational incidents                                     | operational_incidents: open/acknowledged, scoped to roles allowed by the existing incidents API                                                                                                                       |

No aggregate loads full order, customer or approval datasets. Navigation metadata uses small branch/definition lookups, each eligible badge one aggregate query, and only the latest 30 own notifications. No public realtime feed or new subscriptions were added: one in-flight fetch, a 30-second visible-tab refresh, focus/visibility refresh and debounced post-commit invalidation provide bounded updates. The common web API helper emits a non-sensitive local event after successful mutations. Hidden tabs pause scheduled work. Queries remain nonblocking for route content.

Refresh starts with empty badges; failures clear confirmed values, show unavailable and do not fabricate zero. The client aborts after eight seconds and on unmount. Server auth denials clear identity/notifications and redirect to login/account as appropriate. Permissions/branch changes remount protected content; server route guards and existing API authorization remain independent of menu visibility. The controlled QA server outage produced 0 badges while all 28 links remained; recovery in a fresh tab restored the actual count. Next development HMR interrupted the old tab during server restart, so that observation is not a production-network reconnection benchmark.
