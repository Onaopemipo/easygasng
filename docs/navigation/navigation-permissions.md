# Navigation permissions and session boundaries

The repository uses current database roles and branch scope, not granular permission strings. Navigation items name their existing backend read actions and mirror their actual allowlists. The route matrix records these mappings. No roles, grants, approval quorums or database policies were added or weakened.

`navigation.access` authenticates through the same `actor()` session lookup as every protected API. It rejects inactive users, expired/revoked sessions, non-staff roles and inactive/missing non-owner branches. Settings and Approval Centre also require visible setting definitions in the authenticated branch. Empty groups are omitted. Drivers and technicians are further restricted to their assignment-focused experiences.

Every administration page now resolves this metadata on the server before rendering. Unauthenticated visitors go to login; unauthorised/unknown paths return not-found without rendering protected modules. Direct API requests still enforce existing role, branch, assignment, qualification and approval rules. A navigation allowlist never grants a business mutation. Inner legacy operation tabs may still expose a guarded action that the existing API denies; this redesign does not rewrite those modules or their policies.

Owner branch/global scopes are preserved per existing API. Non-owner metadata and counters use the assigned branch. Counter inputs cannot select another branch or impersonate a role. Audit History preserves its existing owner/technical-administrator global-read allowance; navigation did not expand it.

The client revalidates on visible-tab intervals, focus, route changes, refresh and committed web actions. Identity/role/branch changes update links and remount protected content; auth failures clear protected identity, notifications and badges before redirecting. Existing approved access changes revoke target sessions. Sign-out ignores late identity responses and performs a full login navigation to clear protected client-router payloads as well as revoking the session. Live QA exercised a synthetic owner → inventory change through the existing manager request plus independent owner/finance reviews: the old session automatically returned to login, with no protected links/content; reauthentication exposed only inventory-role routes. The same approved workflow restored the synthetic account. Only the isolated QA database was changed.

Automated tests cover customer/anonymous denial, all existing staff role read-action mappings, two-branch isolation, restricted counters, role changes, suspension, expiry/logout, valid/revoked delegation, recipient/requester separation and private-schema runtime grants. Native driver/technician source files are unchanged.
