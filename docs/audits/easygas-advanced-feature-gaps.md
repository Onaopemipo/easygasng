## Dependency order and acceptance

R0 = confirmed integrity/safety fixes; R1 = core launch hardening; R2 = complete operations; R3 = optional pilot differentiators; R4 = integration/analytics expansion. These are proposed delivery phases, not the audit prompt's numbered phases. Ranges are one experienced engineer's working days plus review and exclude provider approval, legal, native store lead time and field validation; do not add them into a promised release date. Every feature requires scoped database/API tests, real UI validation, observability and rollback criteria before “VERIFIED COMPLETE”.

AutoPilot maturity today is **basic reporting with threshold/refill signals**. Predictive business intelligence, interactive assistant and approval-controlled autonomous recommendation actions were not found. Demand Radar is not implemented merely because a product has a reorder threshold. A message-outbox row is not WhatsApp Concierge. A serial number is not QR scanning. A wallet balance is not a savings goal or regulated savings account.

Highest near-term value is correcting core checkout/safety/financial reliability, then validated reminders and branch operations. Optional pilots should be selected using measured customer demand and operating costs; this audit does not invent ROI, conversion increases or future revenue.
