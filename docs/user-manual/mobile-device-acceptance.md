# Mobile role acceptance and corrected behaviour

21 November 2026. The four requested acceptance stages are complete for the current Expo Go source preview. No new native binary was built or installed. Historical PDF/Word editions are retained.

**Customer and commercial refunds:** enter a positive whole quantity within the remaining units or grams, a reason and explicit purchase-credit consent. Retry a failed lookup using **Retry refundable quantities**. If a submission response is uncertain, retry unchanged details; the operation key is retained. Success locks submission and means pending independent review. An approved partial refund reduces the remaining quantity; rejection creates no wallet credit. The refund card now follows the app’s Appearance preference consistently in light and dark modes.

**Owner and finance review:** find the request in **Workspaces → Credits & refunds**, open the correct record, then choose **Actions for this record → Review credit or refund**. Review the selected record, decision and reason before confirming. A password challenge preserves these details; successful verification now clears the obsolete warning. Opening an older record from a later page or search keeps that exact record bound through a scoped refresh. If it is no longer available, refresh the workspace rather than choose a substitute. Money is shown in naira and labelled **Amount (₦)**.

**Other staff:** Manager, Driver and Technician do not receive financial review access. Customer and commercial accounts submit their own eligible requests; they do not approve them. The server still rejects self-review and unauthorised requests even if a client attempts them.

**Driver evidence:** acknowledgement text no longer populates delivery-failure evidence. Enter a fresh observed problem and dispatch note before reporting failure. A picked-up assignment no longer tells you to renew it before responding. Photo consent, description, payment and proof requirements still apply; an unavailable camera reports that limitation and does not permit completion.

**Forms, notifications and jobs:** missing required choices now identify the field (for example, **Choose Vehicle**) before an API call. Zero remains a valid odometer value, and optional consent stays optional. Notifications support marking read and paging. Technician job and business-workspace failures retain Retry/Refresh actions; recovered results come from the server.

Seven representative roles were observed in the iOS simulator. Six related components were exercised through current app navigation; legacy DriverOperations was tested separately in a labelled native harness because current driver routing bypasses it. Service-material rendering variants used synthetic props and did not issue or consume stock. No actual photo/GPS permission, physical fulfilment, hosted refund/credit or new hosted safety qualification was created by this pass.

The simulator is restored to the hosted demo’s original QA owner. The [report](../mobile-device-acceptance/README.md) contains screenshots and acceptance limits; the [matrix](../traceability/mobile-device-acceptance-rtm.md) retains the legacy navigation gap, unsupported ledger GET and all unrelated production gates. These results are not a production launch approval.
