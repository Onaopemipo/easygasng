# Settings change editor update · 20 November 2026

Applies to **Settings** in the business workspace. The existing manual’s role and approval rules still apply.

1. Search for a setting, then choose **Update** or **Propose Change**. The dialog title names the setting. Its header shows the branch, current version and applicable approval requirement.
2. Edit the setting’s fields. For staff access, enter an existing account email and choose **Find account**; check the person’s name and current role before choosing the proposed role. Your own account and inactive accounts cannot be selected. The assigned branch comes from the request scope.
3. Payment settings are organised into **Checkout**, **Fees** and **Wallet**. EasyRewards uses **Points**, **Services** and **Offers**; open an offer to edit it. Switching tabs keeps your changes.
4. Add a short **Reason for change**. Open **Schedule for later** only when needed; the selected day uses Lagos time and remains subject to server scheduling limits, approvals and activation checks.
5. Choose **Review change**. Check the proposed values, reason and timing. Nothing is submitted by opening Review. Choose **Back** to edit, or use the final action to confirm.
6. If **Confirm it’s you** appears, enter your current password and choose **Verify & submit**. The proposed changes stay in the editor if verification fails.

**Save draft** opens a draft review, followed by a separate final **Save draft** action. A saved draft stays inactive and does not enter the approval queue. The Approval Centre remains the place to resume and submit it.

Cancel, the close icon and Escape ask before discarding unsaved changes. Keep editing preserves them. During submission, controls are disabled and closing is temporarily blocked. A version conflict means the underlying setting changed: preserve your intended values, close the editor, refresh and review the current setting before submitting again.

The approval badge is authoritative UI guidance from the server. Eligible sole-Admin business changes can use automatic approval; protected access/payment changes and qualified activation checks keep their existing requirements. This redesign changes presentation, not approval authority.
