# Review and publish customer feedback

Open **Customer Testimonials → Feedback → Review feedback** as the business owner. The review and moderation dialogs are centred. Long content scrolls inside the dialog, and actions stay clear of the client-demo notice.

The status explains the next step:

| Status | Next step |
| --- | --- |
| Draft | Private feedback saved by the customer. Ask the customer to open **Account → Your reviews** and choose **Submit for review**. Consent alone does not submit a draft. Staff cannot submit it for the customer. |
| Pending review | Review the original text and consent. Choose **Approve testimonial**, select a review category and provide a reason. Approval keeps the review private. |
| Approved | Choose **Publish testimonial**, review the confirmation and enter a publication reason. Approval and publication are separate actions. |
| Published | The review is public. Choose **Hide testimonial** with a reason to remove it from public display. |
| Hidden | Publication can be restored when the approved version and consent remain valid. |
| Changes requested | The customer edits their own feedback and submits it for review again. |
| Withdrawn / Rejected | No publication action is available. Withdrawal removes public access; a rejected submission is closed. |

After approval, the same feedback reopens with **Ready to publish** and a prominent **Publish testimonial** action. After publication or hiding, the current status and available action update in place. **Versions & history** retains original text and moderation notes.

Moderation requires current password verification. If prompted, enter your existing password in **Verify your identity**. An incorrect password leaves the review reason in place. Failed decisions retain the confirmation form; cancelling a failed decision does not hide the feedback list. A failed details read offers **Retry feedback details**. Repeated clicks during a pending decision do not submit another request.

Publication still requires explicit customer consent, an eligible completed transaction and approval of the current version. Customer edits return feedback to Draft for a new review. The server rechecks role, consent, eligibility and revision on every action; a previously displayed button does not override these requirements.

This repair publishes application code only. Existing customer feedback is not automatically approved or published. [Verification and rollout](../testimonial-publishing/README.md), [requirements matrix](../traceability/testimonial-publishing-rtm.md).
