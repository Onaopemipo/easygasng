# Signing in and recovering an EasyGas account

Use **Sign In** to enter your email or activated, verified Nigerian phone number and current password. The eye control shows/hides the password. All account passwords use 8–128 characters. A successful response opens the workspace permitted by your actual account; public registration never selects a staff role.

**Create Account** asks for full name, email and password. Follow the actual server confirmation; the app does not claim verification before the server confirms it. Existing staff invitations must be accepted using their original email link. On first sign-in with a temporary password, enter a different new password to finish setup. Staff access and approval remain controlled by authorised administrators.

Choose **Forgot password?**, enter the account email and select **Send Reset Link**. The same generic message appears whether an account matches. Provider/configuration failures remain errors; a confirmation is not a promise that mail has been delivered. Check the requested email and spam folder. Resend limits still apply; repeatedly tapping does not bypass them.

Open the reset or verification link in EasyGas. If needed choose **Open an account link** on Sign In or Create Account and paste the complete link manually. Only trusted EasyGas origins/app schemes and valid link formats are accepted. Never share the link, password or verification code. Links expire and can be used once. An expired/used reset link requires a fresh request. After resetting, sign in again; existing session revocation rules remain in effect.

For a phone-assisted order, use the issued account-completion link and requested possession code before private order details are shown. Review the applicable terms and complete the existing account; a phone number alone cannot grant access or merge identities.

If a request times out, it may already have completed. Check by signing in or request a fresh account link before retrying. The app never retries authentication automatically or claims offline sign-in success. Non-sensitive entries remain on recoverable errors; password values clear when leaving authentication. Back returns to Sign In/guest browsing, and native bottom tabs return after leaving the authentication presentation. Existing cart, checkout draft and introduction preferences remain governed by their original flows.

Light/Dark/System reuses the existing appearance preference. Web auth has the theme control; native appearance remains in the existing app settings. Scroll when the keyboard or large text requires extra room. Apple/Google sign-in are omitted because this version has no verified existing provider integration.

This redesign is local source/preview work; it has not replaced the deployed website or current TestFlight/store binary. [Verification and release matrix](../traceability/auth-redesign-rtm.md).

On startup, a slow product catalogue does not prevent native sign-in. An unavailable web session check offers **Retry session check**. A corrupt saved cart cannot grant access or stop identity restoration; current product/checkout validation is still required before ordering.


On mobile, Back from recovery or an account link returns to Sign In. Back from Sign In returns to the previous guest page, including a saved checkout step; it does not reopen an old recovery/link screen. Back from Create Account returns to Sign In first. Larger text simplifies decorative artwork and keeps the form scrollable. On Android, scroll the authentication form while the keyboard is open; recovery can be submitted using the visible action above the keyboard.
