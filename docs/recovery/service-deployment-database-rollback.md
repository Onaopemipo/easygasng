# Deployment and database rollback

No deployment was performed. Git main is unborn with no HEAD/known-good committed release. A genuine prior-release rollback cannot be certified. Before a later release, record the signed source/build ID, previous compatible artifact, operator, migration version and backup ID. Retain source/build manifests; do not treat an arbitrary running dev cache as a release artifact.

033 is additive: persistent operation results, trusted private-table access, active-slot unique index and nullable quotation validity. No business records are transformed or removed. Review existing duplicate active slot allocations before applying; an index failure should stop the migration and dependent rollout. The migration runner wraps all pending changes in a transaction and uses a schema_migrations lock. Test migration on an isolated restored copy first. Keep the old compatible interface artifact; retain additive schema on application rollback rather than deleting operation evidence.

On rollout failure: stop rollout; preserve logs/incident; determine actual schema/commit outcome; disable new requests through the approved service-configuration workflow if needed; restore a previously verified compatible application; check sign-in, existing bookings, slot allocations, quote/report history, financial/material references and pending notifications. Record results and owner approval before reopening. Do not reverse committed bookings when reverting code.

Local backup tooling: stop the owning embedded database process, run npm run backup -- create <file>, verify <file>, then restore <file> .data/restores/<new-empty-name>. Passphrases use the protected prompt. Backups are AES-256-GCM authenticated/encrypted and file mode 0600; restore refuses active/existing destinations. Verify schema, row counts, booking/customer/slot relationships, operation outcomes, report/quote references, stock and money before any authorized cut-over. Never restore an old snapshot over newer financial records. Current tests restore into separate in-memory PGlite; off-site managed backups, scheduled monitoring and real release rollback remain unverified/unprovisioned.
