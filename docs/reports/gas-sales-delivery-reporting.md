# Gas sales and delivery reporting

`gas.report` is available to owners, finance and branch managers. Non-owner requests are restricted to the actor's branch; another branch ID is rejected. Filters include date range, location ID, branch, order status, payment status, cylinder capacity, minimum/maximum kg and customer category. The Settings report panel uses the same endpoint for display and export.

Quantities distinguish ordered, reserved, dispatched, delivered, refunded and net sold gas. Ordered quantity includes submitted orders; completed sales exclude cancelled and fully refunded orders. Gas revenue is the sum of recorded gas-line subtotals. Delivery revenue includes one stored fee per eligible delivered order. Verified payments are summed from the actual payment ledger; outstanding amounts are distinct. Collected cash is not independently verified money. Existing finance reconciliation reports continue to cover physical products, services, cash awaiting verification, wallet liabilities and operating costs. Revenue is never labelled profit; profit is unavailable without verified cost allocation.

Legacy fixed-refill quantities can be included where migration 025 can infer kg from the immutable original line name; their recorded unit prices determine revenue. Ambiguous legacy quantities are not invented. Historical location names come from order snapshots; older unlinked orders are explicitly labelled historical/unlinked. Location, day, customer and branch groupings include real counts, delivered quantities, revenue and verified-duration averages where timestamps exist. These summaries do not manufacture predictions or treat incomplete orders as repeat purchases. Existing refill profiles and consented marketing retain their own evidence rules.

CSV and Excel XML are generated from the same filtered order rows. CSV protects against leading spreadsheet formulas; XML and printable HTML escape untrusted names. Print/Save PDF uses the browser's print destination. Browser QA verified the zero-row fixture report and CSV download; pure export tests verify escaping and totals. Excel XML is supported by Excel but is not an XLSX package. Actual PDF print output and large real-data report performance still need acceptance testing. Gas-category/cost-centre dashboards beyond these filters remain in the existing finance module rather than a duplicate financial ledger.
