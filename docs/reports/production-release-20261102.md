# Production release continuation — 2 November 2026

Scope: web plus signed iOS/Android customer and role-specific staff experiences, per the user's explicit answer. Payments remain disconnected and rewards economics/flags remain OFF. No deployment, signing, store submission or customer messaging is authorised by a local test. Existing production NO-GO is preserved.

The implementation adds executable production configuration/database privilege checks, schema/worker readiness probing, serial supervised worker shutdown/recovery, encrypted managed-PostgreSQL backup/isolated restore commands, a non-root container/reverse proxy deployment package, CI validation and native signing build profiles with HTTPS/identifier guards. These controls do not replace business or safety acceptance. No partial physical delivery or multi-tenant rollout is enabled.

## Operator runbook

1. Establish a reviewed Git revision (the current repository has no initial commit), approved web/native release scope, recovery owners and objectives. Keep production secrets outside Git and the Docker build context. Configure a dedicated migration identity separately from the restricted runtime login inheriting `easygas_server`. Runtime must own no tables, have no schema CREATE/admin/BYPASSRLS and use `sslmode=verify-full` with the trusted CA. Run `npm run db:migrate` with migration credentials only; never grant runtime migration privileges.
2. Provision the chosen HTTPS host/database only after the local-only hosting decision is changed. Set APP_URL, DATABASE_URL, EASYGAS_RELEASE_SHA and EASYGAS_BACKGROUND_JOBS=false in a protected environment file. Run `npm run release:check` with runtime credentials. Failure prints redacted check results and exits nonzero. It never activates a programme or claims business approval.
3. Review `deploy/Dockerfile`, `deploy/compose.yml` and `deploy/nginx.conf`. Compose binds only loopback; nginx terminates TLS, limits request rate/body/time and preserves streaming. Configure actual DNS/certificates, supervision and external status alerts. Container startup repeats release checks. The worker serialises cycles, finishes the current transaction on SIGTERM and closes its pool. `/api/status` returns only ready/unavailable and 503 for missing schema or a maintenance completion older than five minutes. `/api/health` retains its basic reachability contract. Configure an external monitor/on-call route; no outbound alerts are sent by this task.
4. Managed backup: install a matching PostgreSQL client and use a dedicated backup identity with complete read coverage. Set DATABASE_URL for that identity, and EASYGAS_BACKUP_KEY_FILE to a 0400/0600 passphrase file, held separately from backups. `npm run backup:postgres -- create /protected/backup.egbackup` uses pg_dump custom format of easygas_private, authenticated AES-GCM encryption, private temporary files, no password arguments, and exclusive destination creation. Bound: 512 MiB compressed archive; larger installations require managed streaming/PITR tooling. Schedule encrypted off-site copying/retention with the platform service; this code does not invent an off-site storage account.
5. `npm run backup:postgres -- verify /protected/backup.egbackup` authenticates/decrypts and checks archive readability; this is explicitly NOT a restore drill. Pre-create an isolated empty database named easygas_restore_<label>. Set EASYGAS_RESTORE_URL and EASYGAS_RESTORE_CONFIRM to that exact name, then run `npm run backup:postgres -- restore /protected/backup.egbackup`. Existing objects, source-name reuse and unconfirmed targets are rejected. Restore is one transaction without DROP/CLEAN. Cluster roles must already exist; pg_dump excludes ownership/privilege grants. Reapply reviewed runtime grants/policies with a migration identity and reconcile money/stock/jobs before any cutover. The command does not switch the active database, delete the backup or certify RPO/RTO.
6. CI definition runs all tests with isolated PostgreSQL, web build/types/security audit and native types/both-platform exports/audit. It uploads web evidence even on failure. It cannot run remotely before a reviewed repository/CI connection exists. Native production builds use apps/mobile/eas.json and require public HTTPS EXPO_PUBLIC_API_URL (origin only), ownership confirmation for com.easygasng.customer, EAS project/account and actual Apple/Android signing identities. Do not upload store signing secrets into source. No arbitrary encryption-compliance answer is supplied in app metadata. Run device tests for lifecycle, secure token/offline queue handling, camera/photo consent, tracking, checkout/refunds, themes, accessibility and interrupted requests before submitting signed builds.

## Transactional email continuation

`transactional-mail.ts` adds authenticated SMTP on port 465 or required STARTTLS on 587 with certificate checks, bounded timeouts, no file/URL attachments and no protocol/body logging. EASYGAS_EMAIL_ENABLED remains false. No real email was sent. Configure and verify the actual sender's DNS/authentication and recovery delivery before enabling; release preflight now fails without the configured TLS sender. Implementation follows the [Nodemailer SMTP transport documentation](https://nodemailer.com/smtp).

Only email outbox entries are claimed. Cancelled/consumed/expired challenge entries are suppressed; active recipients and due times are rechecked. A transaction marks a durable failed/uncertain claim and opens a redacted incident before network I/O. Explicit SMTP 4xx rejection backs off; permanent failures, connection timeouts and process crashes require owner review. A stable Message-ID aids diagnosis but is not an SMTP exactly-once guarantee. SMTP acceptance is labelled accordingly. The owner-only Operations → Email panel exposes status/attempts, with no recipient/body/token, and requires recent password verification, a reason and explicit duplicate acknowledgement to retry. Five attempts is the hard maximum. Existing recovery/link revocation semantics are preserved; replies no longer expose local preview tooling in customer-facing recovery text.

Source implementation is complete for the adapter; real provider delivery/DNS, outage and inbox acceptance remain external gates. Privacy retention/erasure still requires an approved data classification/retention policy and controlled fulfilment; it is not silently claimed complete by this continuation.
