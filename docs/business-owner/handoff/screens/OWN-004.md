# OWN-004 — Financial Summary

**Status:** Editable handoff specification. **Actual API handlers, schema names, permission identifiers and nested routes: NEEDS VERIFICATION against repository.**

## Purpose
Give the Business Owner a concise, task-focused view of financial summary.

## Entry and source evidence
- Web: `/admin/finance`. Preserve existing grouped sidebar; do not create competing `/owner/*` routes.
- Mobile: More → Finance; Home / Operations / Approvals / Reports / More tabs.
- Evidence: previously supplied signed-in EasyGas screenshots, role privileges reference and approved Business Owner concept. Exact endpoint contracts were not supplied.

## Data contract
Recognised revenue, receipts, expenses, profit, refunds, wallet liability, receivables, unsettled payments. All values must be server-authoritative, branch-scoped and tied to a defined period and metric basis. **API read handler, database entities, query and freshness guarantee: NEEDS VERIFICATION.**

## Permissions
Scoped finance read. Enforce role defaults, per-user grants/revocations, branch scope, record ownership, independent approval and step-up requirements **on the server**. Exact permission keys and precedence: **NEEDS VERIFICATION**.

## Primary interactions
Drilldown, reconciliation, authorised export. Preserve filter state when returning from detail screens. Every button must resolve to an existing verified workflow.

## Business safeguards
Wallet liability is not revenue; invoices are not verified receipts; pending payment is not settled. Missing profit inputs = Unavailable.

## Desktop layout
- Existing sidebar remains unchanged; workspace fills remaining width with responsive gutters.
- Compact header with title, scope, reporting period where applicable, last confirmed refresh.
- Place priority information and main action first; use 12-column responsive content grid.
- Use compact cards, readable tables with pagination and contextual modals for short forms.
- No decorative charts without dated backend series; charts need text equivalents.

## Mobile web, iOS and Android
- One-column task-first layout with safe-area and keyboard handling.
- Bottom navigation Home, Operations, Approvals, Reports, More.
- Short filters in bottom sheets; sensitive decisions on full detail screens.
- Keep one obvious primary action and accessible 44pt/48dp touch targets.
- Support light/dark/system themes and reduced motion.

## Required states
| State | Design behaviour |
|---|---|
| Loading | Skeleton or existing EasyGas central loader; no fake values |
| Empty | Explain no authorised matching records; reset filters where useful |
| Unavailable | Show “Unavailable”, not zero, and the reason if known |
| Stale | Show last confirmed refresh and retry |
| Offline | Clearly mark cached data; prohibit sensitive offline commits |
| Permission revoked | Hide actions, reject on server, clear restricted cache |
| Validation error | Plain-language message adjacent to the field/action |
| Concurrent conflict | Refresh server state and explain what changed |
| Success | Only after authoritative server confirmation |
