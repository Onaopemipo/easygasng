# Delivery map pin area check — 28 November 2026

A confirmed checkbox previously proved only that the customer bound a coordinate to the written address. It accepted an Australian coordinate for Victoria Island. The shared geographic guard now blocks that selection in web/native pickers and in gas review/final confirmation. GPS, map taps, pasted coordinates/links and saved pins use the same rule. Customers see the selected area and a correction message; the checkbox is disabled until a suitable pin is chosen. Changing the area, address or governed boundary invalidates confirmation. The map initially centres on the selected area.

The server independently resolves the canonical delivery location ID/name and branch, reads the governed setting under a shared lock and checks geography before checkout/reservation, saved-address or phone-profile/destination changes. Client-supplied names, checkbox state or map bounds cannot change that policy. Missing pins on historical/assisted flows retain existing behaviour; no existing order/address is rewritten. Street-level operational coverage checks remain.

## Geographic data and precision

`settings` key `location.<id>` supports optional `mapBounds`: south/north latitude and west/east longitude. Admin → Settings → Delivery Locations → edit the area → **Delivery map boundary**. Enter the business-approved rectangle if the initial locality extent is unsuitable. Existing single Admin approval, audit, versioning and staff review rules apply. Invalid rectangles are rejected; unknown/unconfigured localities cannot confirm a new pin. The public gas catalogue and private phone profile expose only the area metadata/bounds required for the same client check. Product/combined checkout uses the same catalogue areas.

Initial versioned guards are **coarse locality rectangles**, not legal boundaries, exact polygons, reverse-geocoded property verification or proof that every street is serviceable. Victoria Island uses the Nominatim town extent for [OSM node501471396](https://www.openstreetmap.org/node/501471396); Lagos Island uses the island extent for [relation7644528](https://www.openstreetmap.org/relation/7644528); Ajah uses the town extent for [node501483975](https://www.openstreetmap.org/node/501483975). These public place extents were retrieved from the [Nominatim search API](https://nominatim.openstreetmap.org/search?format=jsonv2&q=Victoria%20Island%2C%20Lagos%2C%20Nigeria) on28 November2026. Nominatim's first Lagos Island result is a much broader administrative relation and was deliberately not used. Its Lekki search did not return an unambiguous local-town boundary; the Lekki default is an explicitly conservative engineering corridor envelope (6.38–6.56N,3.43–3.65E), pending business-specific refinement. Locality extents can overlap and do not distinguish every neighbouring street. **Exact property/complex area membership is not claimed.** Tighten the governed rectangle to the actual business service area when needed. No external geocoder receives customers' coordinates; the application check runs locally and server-side from versioned data. Existing map tiles are unchanged.
