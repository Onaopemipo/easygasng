# Accessibility and performance

Web uses status/label/busy for unknown work and progressbar/value only for genuine numeric work. Graphic SVG is hidden from assistive technology; no repeated announcements on animation frames. No focusable SVG, modal role, focus trap, body scroll lock, keyboard handlers or new text in graphic. Existing action labels remain. Overlay is a caller-owned blocking container, not an autonomous modal; preserve host cancellation/error behavior. Native one accessible progressbar hides vector descendants and uses font-free graphics.

Browser prefers-reduced-motion is CSS-first, SSR-safe. Native listens to ReduceMotionChanged/AppState and starts static until preference query resolves. IntersectionObserver/document visibility and native visible/background controls pause motion. Native animations use isInteraction:false/native driver and cleanup; no setInterval/requestAnimationFrame. Smoothness, GPU memory/bundle measurement on low-end real Android and manual screen-reader announcement behavior remain NOT VERIFIED. SVG adds a compatible native dependency; exact device/bundle impact needs the later approved native build. Track is intentionally pale/decorative, active arc and accessible status carry the loading state; formal non-text contrast audit is pending.

Measured isolated web loader minified/gzip byte counts are in evidence/bundle-observation.json (React/existing Lucide external). This is a bounded component-size observation, not route-level bundle delta, frame-rate or native/device performance acceptance. No heavy animation/video dependency added; native SVG is the single compatible graphics dependency.
