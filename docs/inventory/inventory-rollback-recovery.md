# Inventory rollback and recovery

No schema migration, production data import or ledger rewrite. `.data/inventory-preflight-source.tgz` is source-only before changes. Repository is unborn main with all16 top-level entries untracked; do not reset/clean/force checkout. Extract to a separate directory, compare and restore ONLY this phase, preserving prior admin/customer/driver/technician work. The new InventoryWorkspace mount and read facade can be reverted as an application change after reviewed caller restoration; do not reverse real business transactions or drop prior schema.

Receipt failure: transaction rolls back stock/movement/receipt together; lost response uses original reference/payload. Transfer failure: retain valid reservation/transit/damage state and reconcile actual custody before reissue. Adjustment failure: retain original stock/approval; stale before/reserved snapshot requires new verified request. Return: keep held until qualified release, never assume payment refund. Database outage: block new writes, read original outcome after recovery. Notification outage: stock authority remains committed; retry/reconcile messaging separately. Browser stale cache is not stock confirmation.

Existing encrypted backup/isolated restore, independent PostgreSQL stock concurrency and failure tests are included in final suite. Do not call this a production restore drill or invented RTO/RPO. Business-approved RTO/RPO, production backup destination, physical stock/custody and operator restore signoff remain prerequisites. Manual fallback records requests/evidence separately and reconciles independently before posting; never promises stock availability.
