# Mobile web correction delivery

The existing app was extended. Guest cart state no longer reloads on home/non-home catalogue refreshes, login/registration preserve safe checkout return paths, and the customer header keeps the cart visible. Initial cart hydration completes before rendering an empty-cart screen. Products and quantities remain local; authoritative prices, stock and checkout ownership remain server-controlled.

Mobile controls use at least16px text to avoid iOS focus zoom, and cart/form widths wrap within the viewport. The initial public layout did not reproduce general page overflow, so these browser observations do not claim to prove the original physical-device cause. Actual local browser checks covered320/390px, light/dark checkout, registration and authenticated dashboard access.

Credit/debit card is now a direct order checkout arrangement, reusing the existing Paystack quote, consent, initialization, verification and receipt machinery. Migration073 adds a nullable order target to payment intents; old invoice/service/wallet targets remain constrained and unchanged. Existing paid/cancelled orders, foreign identities, partial direct-order amounts and unpaid dispatch are rejected. No receipt/payment success follows from a redirect. Processing fees display to two decimal places and stay separate from the order principal. The financial ledger receives only the verified principal once. Delivery requires no cash for a verified card order; invoices are still issued separately by finance. Once an invoice exists, its reviewed balance/corrections govern payment.

Only already configured and approved sandbox gateway capability exposes the card option. Neither live payments nor a provider credential was activated for this correction. Automated provider responses are explicitly synthetic mocks; they are not merchant-hosted sandbox acceptance.

Root route loading uses the full-screen central loader. Page and local/action loading containers are distinct. The actual full-screen component was rendered with application CSS in a component-only preview; at390×844 the graphic centre is195×422. Section indicators are not forced over the whole screen.

Verification evidence is under [evidence](evidence/). Real local registration preserved the existing two-unit guest cart. The first broad run identified the intentionally changed payment audit hash and a fixture pinned to the previous local schema marker. The original hash baseline remains archived; the authorised MWEB-03 change has a separately recorded reviewed hash, and restricted-runtime fixtures now import the same local schema revision as the runtime. Final results and coverage are recorded in the [matrix](../traceability/mobile-web-corrections-rtm.json).

Deployment has not been performed. Managed environments must apply migration073 through the normal migration process before serving this version. A rollback must retain all intents, verified payments and receipts; pending direct-card orders require reconciliation using the compatible payment implementation. Do not drop the new target column or erase financial records. Existing production NO-GO and Excel import holds remain in force.
